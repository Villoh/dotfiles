# Pi theme from DMS Matugen

DMS generates Pi's `dankcolors` theme from the active Material palette:

- Matugen config fragment: `dot_config/matugen/dms/configs/pi.toml`
- JSON template: `dot_config/matugen/dms/templates/pi.json`
- Generated theme: `~/.pi/agent/themes/dankcolors.json` (do not track; DMS owns it)

Chezmoi symlinks the config and template into `~/.config/matugen/dms/`. DMS
regenerates the theme when wallpaper or theme changes. Select `dankcolors` in Pi
once through `/settings`.

## Important config rule

DMS merges files under `~/.config/matugen/dms/configs/` into its own Matugen
configuration. Keep `pi.toml` as a `[templates.pi]` fragment. Do **not** add a
`[config]` table: DMS already provides one, and duplicate tables fail Matugen
with `duplicate key \`config\` in document root`, breaking every theme worker.

Use absolute paths in `input_path` and `output_path`. Use standard Matugen
colors such as `{{colors.primary.default.hex}}` for surfaces and text, and DMS
palette colors such as `{{dank16.color2.default.hex}}` for distinct ANSI,
syntax, and diff colors. `dank16` exists in DMS's worker context, not plain
Matugen; inject it when testing the template standalone.

## Troubleshooting

- Inspect DMS logs: `journalctl --user -u dms --since '10 minutes ago' --no-pager`.
- On a worker failure mentioning duplicate `config`, remove `[config]` from the
  custom fragment; keep template definitions under `[templates.<name>]`.
- Validate a template with Matugen using a temporary merged config containing
  one `[config]` table plus the custom `[templates.<name>]` entry. Render to a
  temporary output path so the real Pi theme is untouched.
- Change wallpaper/theme in DMS to regenerate; then check
  `~/.pi/agent/themes/dankcolors.json` and select it with Pi `/settings`.
