# NixOS

Current Linux target: NixOS + Hyprland + [Dank Material Shell](https://danklinux.com) (DMS).
Installation guide: [`docs/install/nixos-dms.md`](../../install/nixos-dms.md).

## Ownership boundary

| Owner | Manages |
| ----- | ------- |
| NixOS repo (`~/development/personal/projects/nixos-config`) | OS, packages, services, hardware, boot, Hyprland, DMS, greeter, gaming, Flatpak |
| chezmoi (this repo) | Personal dotfiles, templates, scripts, secrets |

Never let both manage the same file. Package installation belongs in the NixOS
repo; do not add pacman/AUR/imperative bootstrap logic here.

## NixOS repo layout

| Path | Contents |
| ---- | -------- |
| `flake.nix` / `flake.lock` | Inputs (nixpkgs unstable, Home Manager, nix-flatpak, DMS plugin registry, ...) and hosts |
| `hosts/<host>/` | Per-host config and its own `hardware-configuration.nix` (`desktop`, `zenbook`) |
| `modules/nixos/` | System modules: `core`, `desktop` (Hyprland, DMS, greeter, portals), `gaming`, ... |
| `modules/home/` | Home Manager modules: `shell`, `terminals`, `desktop`, `development`, `communication`, ... |
| `docs/` | Install guides (desktop, laptop), dual boot, Secure Boot, maintenance |

Never reuse one host's `hardware-configuration.nix` on another machine.

## Daily commands

Run from the NixOS repo. `NH_OS_FLAKE` is already exported in `dot_zshrc`
(`~/development/personal/projects/nixos-config#desktop`).

```bash
git diff                              # review before applying
nix flake check                       # validate after config/input changes
sudo nixos-rebuild test --flake .#desktop   # temporary activation, boot config untouched
nh os test                            # same via nh
nh os switch                          # make permanent (run manually, after test)
```

Rules: test before switch, keep old generations until the new one is proven,
no automatic `switch`/`boot` or destructive cleanup. Details live in the NixOS
repo under `docs/maintenance/` (updates, `nh`, recovery, cleanup).

## DMS + Hyprland

- DMS starts through UWSM's `graphical-session.target` (`modules/nixos/desktop/dms.nix`).
  Do not also run `dms run` from the Hyprland config: it launches two instances.
- DankGreeter is the login screen; pick `Hyprland (uwsm-managed)`.
- Compositor defaults are deployed once with
  `dms setup headless --compositor hyprland --skip-existing`. Generated files live
  in `~/.config/hypr/dms/`; do not manage them with chezmoi or Home Manager.
- DMS settings tracked here: `dot_config/DankMaterialShell/settings.json` and the
  GPG-encrypted `encrypted_plugin_settings.json.asc`. Both are ignored when
  `enable_dms` is off.
- Matugen templates: `dot_config/matugen/`.
